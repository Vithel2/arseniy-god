# Подпись Android APK

Для обновления установленного APK Android требует тот же ключ подписи, которым был подписан установленный APK. Найти пароль по APK или восстановить утраченный ключ нельзя. Перед заменой приложения сохраните игровой прогресс через настройки игры.

Проверьте архив `ArseniyGod-release-APK` именно от той сборки, которую вы устанавливали: прежняя сборка могла положить туда `GENERATED-release.jks`. Если файл найден, храните его закрыто: он позволяет подписывать версии приложения. Для старого автоматически созданного ключа сборка использовала alias `arseniygod` и пароль `android`; используйте их только для этого старого ключа. Ключ, попавший в доступный другим артефакт, следует считать раскрытым: для надёжной подписи создайте новый закрытый ключ. После сохранения нужной копии удалите из GitHub артефакт, содержащий закрытый ключ.

Если старый ключ не найден, создайте **один новый постоянный ключ** на своём компьютере с установленным JDK:

```sh
keytool -genkeypair -v -keystore arseniy-release.jks -alias arseniygod -keyalg RSA -keysize 3072 -validity 10000
```

Keytool попросит пароль и данные владельца. Храните файл и пароль в надёжном месте с резервной копией. Не отправляйте их в чат и не добавляйте файл ключа в репозиторий. На Windows для преобразования файла в Base64 можно выполнить в PowerShell:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes('arseniy-release.jks')) | Set-Clipboard
```

В настройках GitHub репозитория откройте Settings → Secrets and variables → Actions и добавьте секреты: `KEYSTORE_BASE64` (скопированное значение), `KEYSTORE_PASSWORD` (пароль файла), `KEY_ALIAS` (например, `arseniygod`) и `KEY_PASSWORD` (пароль ключа). Значения вводятся только в GitHub Secrets. Если оба пароля совпадают, введите его в оба секрета.

Если секреты подписи не настроены, сборка создаёт отладочный APK для проверки. Он подписан временным отладочным ключом, не предназначен для выпуска и, скорее всего, не установится поверх предыдущей версии. Release-сборка использует только настроенный постоянный ключ и не публикует его в артефактах. Первая версия с новым ключом не обновит APK, подписанный старым ключом; после сохранения прогресса может понадобиться удалить старую версию, установить новую и восстановить сохранение. Последующие версии с тем же ключом смогут обновляться поверх неё. Новая подпись сама по себе не доказывает причину предупреждения iQOO и не гарантирует его исчезновение.
